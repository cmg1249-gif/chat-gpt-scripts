Run **webcam_server.exe** on the sharing computer and connect from **viewer.exe** with your username and private owner password. The host stays in the tray. This restores the **v2.0.2 setup experience** with the browser dashboard, viewing/audio controls and host PowerShell/Bash terminal.

- No host pairing window, code, approval click or viewer-generated host package.
- First-ever connections can use the internet. Automatic mode tries encrypted LAN port **2220** first, then Cloudflare and an independent Pinggy TLS relay.
- This is an **owner build**: only the public verification key is in the downloads. The matching private connection password is supplied separately to the owner and is never published. Arbitrary newly chosen passwords will not work. On the owner's configured viewer, the saved private credential can be used by leaving the password field blank.
- Signatures bind the login to its destination and certificate. Wrong credentials, altered/expired/replayed logins and forwarding to another destination are rejected. A new viewer connection replaces the previous session. Capture and shell start off; tray Stop and viewer Disconnect close them.
- A matching packaged Linux viewer can operate the Windows `.exe` host. Windows and Linux bundles include their respective viewer, host and diagnostic binaries; standalone Windows EXEs and the Linux host ELF are also provided.

Both diagnostic executables passed **62 control/security checks**. Actual Windows/Linux host/viewer tests passed LAN connection, restart, first internet login through each provider, shell commands and cleanup. The Linux viewer also passed a real internet connection to the Windows host. A live primary-route failure recovered through Pinggy and preserved the shell with discovery unavailable. The final browser dashboard and normal Windows tray startup were checked; Windows media/cursor and Linux media/platform suites passed 34 and 33 checks respectively. Public archives and embedded executable modules were audited to exclude the private owner password and signing seed. SHA-256 manifests identify the tested binaries.

The school network was unavailable for testing. The VM displayed a black screen, so a completed VM test is not claimed; Windows tray testing was on the owner PC. Both internet routes still share ntfy discovery, and blocked services can prevent connection despite ordinary internet access. Automatic discovery assumes one active host for this owner build. Linux targets x86_64 Ubuntu 24.04/glibc 2.39 with X11/tray and appropriate audio backends. See the bundled README and VALIDATION for setup and limits.
